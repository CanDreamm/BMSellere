# Если реестра нет

Для базы с измеримым охватом нужен исходный список. Поисковая выдача такого списка не заменяет. Приложение не приобрело и не загрузило реестр автоматически.

Практичный первый шаг — запросить у поставщика сведений о бизнесе региональную выборку в XLSX. Можно сравнить предложения сервисов Контур.Фокус, СПАРК, Seldon и других поставщиков; наличие нужной выгрузки, API, полноту по ИП и права последующего использования нужно уточнять у конкретного поставщика до оплаты. Мы не утверждаем, что любой их тариф даёт массовую выгрузку.

Текст запроса поставщику:

> Нужна выборка действующих юридических лиц и индивидуальных предпринимателей, зарегистрированных в Липецкой области (код региона 48). Поля: полное наименование, ИНН текстом, код региона, действующий статус, адрес, основной ОКВЭД/описание, дата актуальности. Нужны количество записей, дата обновления, стоимость, условия использования для собственной CRM и способ регулярного обновления (XLSX по HTTPS или API). Филиалы организаций из других регионов просим оценить отдельной выборкой. Предоставьте небольшой образец до покупки.

Сначала проверьте несколько сотен записей; не покупайте контакты без проверки состава и условий. Почта и сайт не обязательны для реестра: их ищет следующий этап. Права на использование контактов и согласие на рассылку — отдельные вопросы.

Альтернатива — получение сведений из доступных официальных наборов ФНС. Конкретный набор, условия и формат нужно проверить до разработки адаптера. Текущая версия **не импортирует сырые XML/ZIP ЕГРЮЛ/ЕГРИП** и не обходит CAPTCHA сайта ФНС.

## Формат импорта

В `/collector` есть «Скачать шаблон реестра». Обязательные колонки:

| Организация | ИНН | Код региона | Статус |
|---|---|---|---|
| Полное название | 10 или 12 цифр, строка | 48 | действует или active |

Необязательные: `Адрес`, `Описание чем занимаются`. Основной ОКВЭД и дату актуальности храните в исходном файле; отдельных полей для них в текущей схеме нет. Контрольные цифры ИНН проверяются. Ошибочная строка отменяет весь импорт. Строки с другим регионом/статусом пропускаются; ранее загруженная организация с таким ИНН исключается из исследовательского расписания, но не удаляется из базы. Отсутствие организации в следующем файле не означает ликвидацию: автоматического удаления нет.

Для разовой выборки загрузите XLSX. Для регулярного обновления добавьте источник типа «Нормализованный XLSX-реестр от поставщика» с публичным HTTPS URL без встроенных паролей/токенов. Приватный API поставщика требует отдельного адаптера после выбора поставщика. Импорт не включает платный поиск автоматически.

## Поиск по ИНН

1. Получите доступ к официальному [Brave Search API](https://api-dashboard.search.brave.com/). Проверьте тариф, квоту и право использования выдачи.
2. На сервере через `sudoedit /etc/bmseller.env` добавьте `BRAVE_SEARCH_API_KEY=...`. Значение не помещайте в Git и чат. Перезапустите обе службы, чтобы интерфейс увидел настройку, а worker — ключ.
3. В `/collector` выберите записи из реестра и нажмите «Включить поиск для выбранных». Один проход делает до двух поисковых запросов на компанию, до 5 результатов на запрос, до 3 страниц каждого сайта и до 15 уникальных страниц всего. Между загрузками пауза 2 секунды. Очередь пополняется пакетами до 10 компаний; включать можно до 100 показанных записей за действие.
4. Сначала ищется ИНН, затем при отсутствии совпадений — название, адрес и ИНН. Несовпадающий ИНН и известные справочники не принимаются за совпадение сайта. Совпадение ИНН на сайте само по себе не доказывает, что сайт официальный; оператор проверяет это.
5. Кандидаты и источники каждого найденного поля показываются в интерфейсе. Подтверждение заполняет пустые поля компании, не меняя согласие и существующие данные оператора. При нескольких сайтах проверьте каждую карточку отдельно. Несколько брендов пока хранятся как отдельные кандидатные карточки, а основная запись компании имеет одно текстовое поле бренда.
6. При отсутствии сайта следующий проход через 7 дней, при найденном — через 30. Ошибки повторяются через 1, 2, 4 и далее до 168 часов. Нет ключа — API не вызывается. Пауза останавливает дальнейшее планирование; уже поставленное задание может выполниться. Повторное «Включить поиск» сбрасывает время ожидания, но не дублирует активное задание.

Старый Bing RSS и обход конкретных каталогов сохранены как дополнительные способы обнаружения. Они не заменяют реестр и официальный API в новой цепочке.

Пока не реализованы Playwright для динамических сайтов, генерация описаний ИИ, адаптер конкретного поставщика реестра и автоматическое подтверждение официальности/брендов. Реальные API-вызовы не проверены без ключа; тесты используют контролируемые ответы. Доступ к найденным сайтам требует исходящего HTTP(S) и сетевой изоляции сборщика, описанной в SERVER.md.
