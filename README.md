# BMSeller

Первая версия веб-приложения на Python для базы организаций и ИП, сбора контактов и отправки КП. Интерфейс на русском, серверный рендеринг Flask, SQLite, отдельный обработчик заданий. Node.js не требуется.

## Установка на сервер

Полная инструкция с нуля для Ubuntu 24.04: [deploy/SERVER.md](deploy/SERVER.md). Включает Gunicorn, Nginx, HTTPS, systemd, настройки SMTP, обновления и резервные копии.

## Локальный запуск

Python 3.12+:

```sh
cd /workspace/BMSellere
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python app.py
```

В другом терминале в том же каталоге:

```sh
.venv/bin/python worker.py
```

По умолчанию приложение слушает только 127.0.0.1:8000. Для сервера задайте `APP_PASSWORD` (логин `admin`), используйте WSGI-сервер и HTTPS reverse proxy. Flask development server предназначен для разработки. Не публикуйте без HTTPS. Данные и презентации находятся в `data/`; резервируйте весь каталог. Секреты передаются через окружение, `.env` автоматически не загружается.

## Работа

1. Загрузите XLSX с колонками `Организация`, `ИНН`, `Бренд`, `Описание чем занимаются`, `Адрес`, `Телефон`, `Почта`, `Сайт`. Первые две обязательны. ИНН храните текстом. Повторный импорт обновляет по ИНН, пустые ячейки не стирают сведения. Ошибка строки отменяет весь импорт. Импорт не устанавливает согласие на рассылку.
2. Выберите компании с известным сайтом и нажмите «Собрать контакты с сайтов». Обработчик читает главную страницу и до двух страниц контактов, собирает опубликованные email и телефоны. Найденные контакты — кандидаты для ручной проверки. Уже заполненные контакты не заменяются.
3. Создайте КП с текстом и PDF-презентацией. Подстановки: `{{organization}}`, `{{brand}}`. Раскройте сохранённое КП для просмотра.
4. Отметьте подтверждённое согласие на рассылку у подходящих контактов, выберите компании и КП, отправьте. Повтор того же КП той же компании блокируется. Исключение контакта учитывается и перед непосредственной отправкой.
5. Экспортируйте базу в Excel. Поиск работает по названию, ИНН, бренду и описанию. Интерфейс показывает до 500 записей, экспорт — всю базу.

### Постоянное пополнение

`COMPANY_FEED_URL` — публичный HTTPS URL разрешённого вам источника XLSX с теми же колонками. Worker скачивает его раз в сутки (`FEED_INTERVAL_SECONDS`). Без источника массовое наполнение не происходит. Отбор действующих организаций региона должен обеспечивать поставщик реестра; приложение не подтверждает статус ФНС самостоятельно.

Каждый час worker ставит до 100 компаний с сайтами в очередь проверки, если они не проверялись 30 дней. После ошибки новая попытка планируется не чаще раза в сутки. Интервал между заданиями — `JOB_DELAY_SECONDS` (по умолчанию 2).

### Почта

Нужны переменные `SMTP_HOST`, `SMTP_PORT` (587), `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`. Используется STARTTLS с проверкой сертификата. Реальную отправку настраивайте через выбранного провайдера: SMTP-доступ зависит от сети сервера. Приложение не отправляет письма при отсутствии настройки SMTP. Секреты не коммитьте.

## Границы первой версии

- Нет подключённого реестра ФНС, поискового API, автоматического поиска неизвестных сайтов и подтверждения брендов. База изначально пустая; фиктивных компаний нет.
- Нет автоматической обработки bounce, входящих ответов и ссылок отписки. Исключение получателя выполняется оператором.
- SQLite подходит для небольшого запуска. Для большой базы и нескольких обработчиков потребуется PostgreSQL и миграции.
- Запись `running` после аварии требует проверки оператором. Автоповтора отправки нет: SMTP мог принять письмо до сбоя. `done` означает принятие SMTP-сервером, а не доставку адресату. Ошибки сохраняются по классу исключения без содержимого сетевых ответов.
- Сбор сайтов рассчитан на доверенный импорт оператором. Для многопользовательского публичного сервиса нужен отдельный сетевой сборщик с жёстким egress-фильтром (включая защиту от DNS rebinding), управление пользователями и аудит согласий.
- Реальная отправка и реальные внешние источники не проверяются тестами; тесты проверяют импорт, экспорт, очередь, ограничения и сбор на контролируемых ответах.

## Структура проекта

- `app.py` — интерфейс, база SQLite, импорт/экспорт, КП и очередь.
- `worker.py` — фоновое пополнение из XLSX, сбор контактов, отправка через SMTP.
- `wsgi.py` — точка входа Gunicorn.
- `templates/` — интерфейс, `tests/` — автоматические проверки.
- `deploy/` — конфигурации сервера и инструкция развёртывания.
- `data/` — локальные данные, исключены из Git.
