# BMSeller

Первая версия веб-приложения на Python для базы организаций и ИП, сбора информации с сайтов и отправки КП. Интерфейс на русском, серверный рендеринг Flask, SQLite, отдельный обработчик заданий. Node.js не требуется.

## Установка на сервер

Полная инструкция с нуля для Ubuntu 24.04: [deploy/SERVER.md](deploy/SERVER.md). Включает Gunicorn, Nginx, HTTPS, systemd, настройки SMTP, обновления и резервные копии.

## Локальный запуск

Python 3.12+:

```sh
cd /workspace/BMSellere
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python app.py
```

В другом терминале в том же каталоге:

```sh
.venv/bin/python worker.py
```

По умолчанию приложение слушает только 127.0.0.1:8000. Для сервера задайте `APP_PASSWORD` (логин `admin`), используйте WSGI-сервер и HTTPS reverse proxy. Flask development server предназначен для разработки. Не публикуйте без HTTPS. Данные и презентации находятся в `data/`; резервируйте весь каталог. Секреты передаются через окружение, `.env` автоматически не загружается.

## Работа

1. Загрузите XLSX с колонками `Организация`, `ИНН`, `Бренд`, `Описание чем занимаются`, `Адрес`, `Телефон`, `Почта`, `Сайт`. Первые две обязательны. ИНН храните текстом. Повторный импорт обновляет по ИНН, пустые ячейки не стирают сведения. Ошибка строки отменяет весь импорт. Импорт не устанавливает согласие на рассылку.
2. Выберите компании с известным сайтом и нажмите «Собрать контакты с сайтов». Обработчик читает главную страницу и до двух страниц контактов, собирает опубликованные email и телефоны. Найденные контакты — кандидаты для ручной проверки. Уже заполненные контакты не заменяются.
3. Создайте КП с текстом и PDF-презентацией. Подстановки: `{{organization}}`, `{{brand}}`. Раскройте сохранённое КП для просмотра.
4. Отметьте подтверждённое согласие на рассылку у подходящих контактов, выберите компании и КП, отправьте. Повтор того же КП той же компании блокируется. Исключение контакта учитывается и перед непосредственной отправкой.
5. Экспортируйте базу в Excel. Поиск работает по названию, ИНН, бренду и описанию. Интерфейс показывает до 500 записей, экспорт — всю базу.

### Сборщик информации

Откройте **«Сборщик информации»** в верхней части интерфейса (`/collector`).

1. В блоке **«Искать компании в интернете»** задайте запросы (один на строку, до 20) и нажмите **«Начать поиск в интернете»**. Предложены запросы по Липецку, области, Ельцу и ИП. Сборщик сам получает ссылки из публичной RSS-выдачи Bing и посещает найденные страницы. API-ключ не нужен. Поисковые задания повторяются раз в 24 часа.
2. Для конкретного известного каталога или сайта можно отдельно добавить название источника, стартовый URL, лимит страниц (1–100) и интервал (1–720 часов).
3. Запустите `worker.py`: он автоматически поставит включённые источники в очередь. Кнопка «Собрать сейчас» запускает внеочередную проверку, «Пауза» отключает будущие запуски по расписанию. Уже поставленные задания не отменяются.
4. Сборщик обходит страницы того же домена до двух переходов от стартовой страницы, с паузой 2 секунды. Извлекаются ИНН с проверкой контрольных цифр, название, предполагаемый бренд, описание, адрес, телефоны и почты. Поддерживаются видимый HTML, `mailto:`, `tel:` и структурированные данные JSON-LD. Названия и описания не генерируются ИИ.
5. Найденные карточки появляются на странице сборщика вместе с URL источника. Проверьте регион, действующий статус, принадлежность контактов и бренд; исправьте поля и подтвердите или отклоните карточку.
6. Подтверждённая карточка добавляется в основную базу и Excel. Для существующего ИНН заполняются только пустые поля; данные оператора и согласие на рассылку сохраняются. Повторный сбор не создаёт копии карточек одного ИНН в одном источнике и не возвращает уже рассмотренные карточки на проверку.

В истории видны запуски и ошибки, в источнике — количество обработанных страниц и найденных карточек. Один worker последовательно выполняет сбор и рассылку; большой обход может задерживать остальные задания. Времена истории выводятся в UTC.

**Ограничения:** поисковые запросы нужно запустить в интерфейсе. Публичный RSS-поиск не имеет гарантии доступности и полноты; при отказе, CAPTCHA или неожиданном формате результат помечается ошибкой, фиктивные карточки не создаются. Поисковые результаты и сайты должны быть доступны серверу по HTTPS; в средах с сетевым allowlist нужны `www.bing.com` и домены найденных сайтов. В этой облачной среде реальный запрос поиска был заблокирован сетевым прокси (403); интеграция проверена контролируемыми RSS/HTML-ответами, а живой поиск здесь пока не подтверждён. Сборщик не является реестром всех компаний региона. Он не исполняет JavaScript, не обходит CAPTCHA и не переходит по внешним ссылкам со страниц сайтов (первоначальные сайты берутся из поисковой выдачи). Страница без корректного ИНН или с несколькими разными ИНН не создаёт карточку. Предположение о бренде по заголовку не доказывает принадлежность бренда. Соблюдайте условия источника и ограничения доступа; используйте разрешённые источники. Сайт без явного ИНН, динамический каталог или API поставщика может потребовать отдельного адаптера.

### Постоянное пополнение

`COMPANY_FEED_URL` — публичный HTTPS URL разрешённого вам источника XLSX с теми же колонками. Worker скачивает его раз в сутки (`FEED_INTERVAL_SECONDS`). Без источника массовое наполнение не происходит. Отбор действующих организаций региона должен обеспечивать поставщик реестра; приложение не подтверждает статус ФНС самостоятельно.

Каждый час worker ставит до 100 компаний с сайтами в очередь проверки, если они не проверялись 30 дней. После ошибки новая попытка планируется не чаще раза в сутки. Интервал между заданиями — `JOB_DELAY_SECONDS` (по умолчанию 2).

### Почта

Для Mail.ru используйте `SMTP_HOST=smtp.mail.ru`, `SMTP_PORT=465`, `SMTP_SECURITY=ssl`. В `SMTP_USER` укажите полный адрес ящика, в `SMTP_FROM` — тот же адрес. В `SMTP_PASSWORD` нужен отдельный пароль для внешнего приложения, созданный в настройках безопасности Mail.ru, а не обычный пароль входа. Заполняйте его только в `/etc/bmseller.env` на сервере, не в Git и не в чате.

Пример уже находится в `deploy/environment.example`. После изменения настроек перезапустите `bmseller-worker`. TLS-сертификат проверяется. Другие провайдеры могут использовать `SMTP_SECURITY=starttls` с портом 587 (режим по умолчанию для прежних настроек). Неизвестные режимы и отправка без TLS не поддерживаются. Реальная отправка через Mail.ru пока не проверена: нужен настроенный ящик и пароль приложения.

## Границы первой версии

- Нет подключённого реестра ФНС и автоматического подтверждения брендов. Поиск неизвестных сайтов работает через публичную RSS-выдачу Bing, без гарантии доступности и полноты. База изначально пустая; фиктивных компаний нет.
- Нет автоматической обработки bounce, входящих ответов и ссылок отписки. Исключение получателя выполняется оператором.
- SQLite подходит для небольшого запуска. Для большой базы и нескольких обработчиков потребуется PostgreSQL и миграции.
- Запись `running` после аварии требует проверки оператором. Автоповтора отправки нет: SMTP мог принять письмо до сбоя. `done` означает принятие SMTP-сервером, а не доставку адресату. Ошибки сохраняются по классу исключения без содержимого сетевых ответов.
- Сбор сайтов проверяет публичность DNS-адресов и URL перенаправлений. Для запуска с недоверенными сайтами из поиска используйте изолированный сервер/контейнер с сетевым запретом доступа сборщика к локальным, частным и служебным сетям (в том числе при DNS rebinding). Одна проверка DNS в приложении такой изоляции не обеспечивает. Для многопользовательского сервиса также нужны управление пользователями и аудит согласий.
- Реальная отправка и реальные внешние источники не проверяются тестами; тесты проверяют импорт, экспорт, очередь, ограничения и сбор на контролируемых ответах.

## Структура проекта

- `app.py` — интерфейс, база SQLite, импорт/экспорт, КП и очередь.
- `worker.py` — расписание источников, фоновое пополнение из XLSX, сбор контактов, отправка через SMTP.
- `collector.py` — ограниченный обход сайтов, проверка ИНН, извлечение карточек на проверку.
- `wsgi.py` — точка входа Gunicorn.
- `templates/` — интерфейс, `tests/` — автоматические проверки.
- `deploy/` — конфигурации сервера и инструкция развёртывания.
- `data/` — локальные данные, исключены из Git.
